# Cammy Control Center (C3)

C3 is the one PC service between agents and Cammy (Adam, 2026-11-16). It replaces the
5-minute `host/cammy_gemini_live.py` sessions. The design and audit are in
`docs/VOICE-PATH-AUDIT-2026-11-16.md`.

## Run it

```
make -C host/c3/aec                       # once: WebRTC echo canceller shim (build/c3/libc3aec.so)
(cd host && ../.venv-live/bin/python -m c3) # runs until Ctrl-C; options: --help
python3 host/c3/gui.py                    # desktop window (also "Cammy Control Center" in Activities)
```

The desktop session uses the `cammy-c3.service` user unit. When enabled it
starts at login with LAB mounted and holds Cammy's control lease. The separate
`cammy-calendar-broker.service` supplies the Calendar tab.

Data is in `private/c3/` (git-ignored):
- `api-token`
- `desktop-token`, an additional private credential for the local desktop
- `logs/c3.log` (5 MB x 3)
- `transcript/<day>.jsonl`, kept 14 days

## Parts (`host/c3/`)

| File | Job |
|---|---|
| `body.py` | One lease, renewed and repaired. Preview and mic are reopened; speaker (one gapless job per reply via `cammy_voicefx.Stream`); face (awake idle while connected, native sleep after lease loss); eyes (one 1 fps preview reader whenever connected); captures |
| `echo.py`, `aec/` | Echo canceller. The reference is the exact PCM sent to the speaker; per-reply offset found by GCC-PHAT; WebRTC AEC3 from the system library, SpeexDSP fallback |
| `moves.py` | Follow me (stock face follow via the DOWN button, state from `/v1/face/status` `tracking`), show the camera (face steps aside for the live view), look around (end-to-end sweep with photos) |
| `listener.py` | Silero speech gate: pre-roll 640 ms, opens after 320 ms of speech, closes after 480 ms of quiet, stricter for barge-in (0.8 for 320 ms) |
| `voice.py` | Gemini Live with manual activity: only gated microphone audio is sent. Sleeps after `--idle` (45 s) and resumes. Runs a separate silent check while idle |
| `transcript.py` | Rolling voice transcript. Legacy T3 mode can forward it in batches. |
| `instructions.py` | Reads, validates and saves profile-scoped Markdown for Gemini Live |
| `api.py` | `127.0.0.1:8792`, bearer token: status, transcript, turn, say, look, capture, sleep/wake, duplex, turn-around, follow, camera-view, look-around |
| `service.py` | Wiring and supervision: each part restarts with backoff; the service runs until stopped |
| `gui.py` | Desktop client for conversation, activity, connection status and voice controls (GTK4/libadwaita, system Python) |

## Desktop window

The left pane opens on **Activity**, with hearing, playback, camera motion and pending
brain requests. **Look around** starts the existing camera sweep. **Connections** shows
the local HTTP endpoint, camera, battery, Gemini voice session, voice health and configured Brain backend. Wake or
sleep the voice session and change duplex for this service run from that tab.

Conversation stays on the right. Enter sends a typed turn to Gemini and Cammy can reply
aloud. **Show events** includes tool, camera and service entries. The window reads the
latest 80 transcript entries, keeps full message text, and follows new turns while you
are at the bottom. A failed send keeps the draft. Below 730 pixels wide, the header
button opens the status sidebar over the conversation. Closing the window leaves C3 running.

**Brain** sends text to the selected local profile. Each profile has its own
instructions, workspace and conversation history. **Providers** shows whether
Codex and Claude Code are installed, signed in and able to complete a request.
Refresh checks local sign-in. Test connection sends a small request through that
provider account and reports the result or a recovery step. Sign-in uses the
provider's own CLI. [Brain setup](BRAIN.md)

## CammyOS maintenance

The **OS** tab shows the running version and boot from the camera. **Inspect
recovery USB** also checks the internal boot files against a saved
installation receipt and shows whether the selected release is present on
the TF card. **Prepare action** verifies the whole TF slot and the supported
camera and stock provenance.

The tab supports first-device setup, install or update, same-release repair
and rollback. Local approval binds an action to the reviewed artifact, USB
transport, device boot and TF card. When the installer finishes, the operator
powers the camera off and on to try the one-shot boot. First-device setup
starts after owner-authorized USB maintenance is available. The first-time
physical steps, local passphrase setup and matching terminal commands are in
[Cammy's technical foundation](CAMMY-BRAIN-FOUNDATION.md#desktop-deployment).
Use the OS tab's **Install and recovery checklist** before an update.
[Checked update and recovery](CAMMY-BRAIN-FOUNDATION.md#checked-update-and-recovery)

## Agent and Skills

**Agent** edits the selected Brain profile's `work/AGENT.md` for names, tone and
behavior. The tab also lists the built-in tools and their descriptions. **Skills**
edits Markdown in `work/skills/<id>.md` for when and how to use those tools,
including any phrasing examples the operator adds. A new profile's first load
seeds seven short notes, including Look Around, Look Back and photo/video
capture.

CCC adds these notes to Gemini Live's built-in persona and sends the tool
definitions alongside it. Gemini uses the intent of the request to choose a tool.
For example, “Tell me what's on both sides of you” can call Look Around. CCC's
code defines what the sweep does. The seven voice defaults now total 1,080
bytes, down from 4,912. CCC uses the compact equivalents when it reads
byte-for-byte older defaults. The editor keeps the saved files and any edits.
The selected profile's Codex or Claude Brain uses its own instructions.

Saves apply on the next Gemini connection. An active conversation keeps its
current guidance. A changed prompt starts a fresh connection with a recent
transcript summary when one is available. The editor keeps drafts per profile
and shows the saved version if an external edit conflicts with a draft. At
narrow widths the channel picker contains Conversation, Brain, Providers,
Look back, Agent and Skills.

The authenticated API serves `GET /v1/instructions` and accepts
`PUT /v1/instructions/agent` and `PUT /v1/instructions/skills/{id}`.
Saves include the profile ID, Markdown text and the last-read revision.

## Look Back

While C3 has a live camera connection, it samples the existing RTSP feed at
one frame per second. It saves JPEGs in the selected resident profile's
`work/.cammy-preview/` folder and replaces the oldest JPEGs when either
14,400 frames (about four hours at 1 fps) or 250 MB of JPEG payload is reached.
Opening the selected profile at startup applies both limits to existing
history. Writes use atomic rename with no per-frame sync, so an abrupt power
loss can lose recent frames. Normal restarts preserve the history. Live
viewing still works without a selected profile.

On 0.7.13 and later, press the physical **M** button beside Record in
CammyOS to pause the CCC microphone and Look Back sampling. Press it
again to resume. CCC shows **Capture muted** while paused and retains
earlier frames. The switch holds through a CCC reconnect within the
same camera boot. Open Settings by tapping the face or pressing OK.

Open **Look Back** to scrub the selected profile's timeline or follow the
newest stored frame. Gaps in capture appear as unavailable times. Ask Cammy to
look back at a time or interval to send a small, timestamped sample from that
profile to Gemini. The local viewer and background capture do not send frames
or wake Gemini.

## Agent and bot access

CCC is the service that owns Cammy's renewable device lease. The desktop and
local scripts use its bearer-authenticated HTTP API on `127.0.0.1:8792`.
The Codex/T3 registration starts `host/cammy_mcp.py` over stdio. Its default
`cammy_c3_*` tools use that same API for status, conversation, motion, capture,
live and historical views, resident Brain turns and read-only provider status.

Look Back labels stored frames with their saved timestamps. Live Look labels
its JPEG with the receive time. Brain messages are private text and require
the named profile to be active at acceptance. The selected profile manages
its own history. Provider setup and Markdown edits are available in CCC itself.

To retain the old finite-session commands for a client that requires them,
register a separate MCP entry using `host/cammy_mcp.py --legacy` and the
old agent service on port 8791. That path keeps thread/session binding,
finite listening and motion, quiet policy and Stop. The default entry point
reports a CCC outage directly.

## Voice commands (0.7.4)

Gemini's tools, also on the API and shown on the window's Camera row:

| Say | Tool | What happens |
|---|---|---|
| "Follow me" / "stop following" | `follow_me(on)` | One DOWN tap if the state differs, then the state is checked. Cammy's screen shows the live view while it follows. |
| "Show the camera" / "show your face" | `show_camera(on)` | The face steps aside for the stock live view |
| "Look around" | `look_around` | Pauses follow, zooms fully out (30 stock zoom-out steps, cmd 4004; the zoom is a digital crop, index 0..30, shown as 1x to about 18x), holds left to the end stop, pans right continuously while sampling up to 6 frames, returns to the middle, and restores follow. C3 waits for speaker playback before starting the sweep, queues audio until the return finishes, and suppresses microphone triggers during motion. About 25 s in the live test (end to end is about 7 s at stock speed, timed on Cammy). The photos come back to Gemini as a `[Look around]` message. |
| "Turn around" | `turn_around` | Turn-180 (stock also switches follow off) |

Firmware older than 0.7.4 does not report the follow state. Then C3 assumes follow is off
at boot and hides the face itself while following.

## Conversation face cues

CCC chooses a face pose from the camera view, speaker activity, local speech
gate and pending reply. Camera view takes priority, followed by speaker playback.
While connected, Cammy uses a listening pose while the local gate is open, a
curious pose while looking or waiting for a reply, and awake neutral idle
otherwise. Waiting begins after a turn is sent
and ends on completion, interruption, disconnect, or eight seconds without reply
activity. Brief changes between calm poses are smoothed to limit LCD flicker.

The camera plays its sleep loop when the face lease is released or expires. An
abrupt connection loss can leave the previous pose visible until the current
lease expires. Speaking uses the firmware's two-frame loop while a speaker job is active.
[Face-loop research](FACE-LOOP-RESEARCH-2026-11-17.md)

## Family

C3 defaults to the family deployment. The Family tab has the family mode,
face selection, Calendar access and local games. Guess the number,
rock-paper-scissors, and sums work from the keyboard. With `--local-voice`,
installed Whisper and Kokoro models can hear and answer game turns on the host.

Kids and Adult modes live in CCC, not on the camera. CCC sets the mode
from the face pack it last knew:

| Face | Mode |
| --- | --- |
| Pikachu, Fin and Fur | Always Kids |
| Cammy | Adult, unless the Kids override is on |
| Unknown, or none reported since C3 started | Kids |

Gemini uses the displayed pack ID when the portal reports it. The supported
IDs are `cammy`, `pikachu`, and `fin-fur`. Missing or unknown IDs use the
neutral Cammy voice persona. Family access uses its own rules above.

From CammyOS 0.8.1, **Settings → Sound & Face** on the camera selects and
saves any available pack. The **Family** tab in CCC offers temporary face
changes during its connection. A new camera-menu selection takes priority.

Adult opens as soon as Cammy reports the Cammy face or a CCC selection of
it is confirmed. Kids stops new camera history and transcript recording and
restricts the camera and ordinary agent API. The authenticated local CCC
window keeps Brain, Providers, saved Look Back, Agent, Skills, and Calendar
available in either camera mode. Text turns started in the local Brain
continue across a camera-mode change. The family deployment uses local play
and desktop text chat.
`--deployment adult-standalone` is for a separate adult-only deployment.

**Kids mode** in the Family tab holds Kids on any face until **Use face
pack**. C3 saves the override in `private/c3/family/mode.json`, so it
survives restarts. An unreadable file holds Kids. Reset never opens Adult on
a Kids or unknown face.

When Cammy goes offline or stops answering, CCC keeps the current mode. A
Cammy grant that ends because its face lease ran out also keeps Adult, even
though the camera then shows the stock pack. CCC switches to Kids when the
camera reports a physical Kids pick, a CCC Kids choice, stock camera mode, a
reboot onto a Kids pack, or an unknown pack. The Family tab marks a face it
can no longer read as "last known".

The Family tab can switch the camera between Cammy and a Kids pack. A Kids
choice applies the camera restrictions before the face changes.

### Calendar access

The desktop PIN is used only for **Calendar access**, the opt-in private
Executor Calendar. The local desktop can unlock its selected profile for up
to 30 minutes (`--calendar-access-minutes`) in either camera mode. Access
closes on a profile change or reselection, expiry, a PIN change or **Lock
Calendar access**. Voice requests on the camera still require Adult mode.
The first PIN needs the setup code in `private/c3/family/setup-code`. Wrong
attempts are rate limited across restarts. Cancel sign-in and Disconnect
work while access is locked.

### Calendar

The Calendar tab connects the selected Brain profile to a scoped Executor
Cloud connection, after Calendar access is open. On Executor's dashboard, give that connection
one Google Calendar account and read-only event-list access. In CCC, enter
the connection ID, sign in in the browser, and run Test. The broker runs
as a separate desktop user service and stores each profile's sign-in under
`private/calendar-broker/`, outside the Brain workspaces.

CCC answers “What's on my schedule tomorrow?” in the Calendar tab. The Brain
routes today, tomorrow and next-event questions locally. With local voice on,
for example say “Hey Cammy, check my schedule tomorrow.” CCC confirms the result
with local speech. Calendar titles and times appear in the desktop view,
with private events masked. They stay out of provider prompts and chat history.

## Duplex

- **`--duplex half`** (default) closes the mic during playback and its echo tail.
- **`auto`**: barge-in for a reply once Echo has converged on it (delay known and echo cut
  by at least 15 dB). Until then, that reply is half duplex.
- **`full`**: barge-in whenever Echo runs.
- **`off`**: no echo canceller.

On a barge-in, C3 cancels the speaker job and sends `activity_start`; Gemini stops and
listens.

Checked offline (2026-11-16):
- Synthetic room with a 180/900 ms offset, speaker distortion and noise: WebRTC removed
  37 dB of echo and converged 1.1 s after Cammy started speaking; the near-end talker lost
  3-4 dB.
- mic -> Echo -> Listener: Cammy alone never opened the gate, and a talker over Cammy did
  (`tests/test_c3.py` FullDuplexPathTests).

On Cammy (2026-11-16, announced test clip): delay 860.6 ms, converged 2.0 s after Cammy
started speaking, echo cut by 42.4 dB median (48.0 dB max), well past the 15 dB `auto`
needs. **Live `auto` failed (2026-11-16):** with Adam talking, ERLE was 21 dB and the last
words of each reply ("my brain", "around your desk") came back as speech, so Cammy answered
itself in a loop and cut its own replies (3 barge-ins in 10 turns). C3 stays half duplex.

Half duplex keeps the mic closed during the speaker job and while Gemini is
sending audio for that reply. CCC budgets 1.3 s after the estimated end of
queued PCM to cover the measured 0.7–0.9 s echo delay and guardian startup.
Terminal playback status keeps the existing deadline with a 250 ms minimum
margin, so the guardian's idle period and the echo guard overlap. The gate
opens after 320 ms of speech. Gemini uses manual activity and is told to answer
only when spoken to. Proactive audio was dropped on 2026-11-21: with it on, gemini-3.8-live gave no reply
or transcription to a clear "Cammy, what is two plus two?" (off: answered in 6.6 s), so TV
and side chatter that pass the speech gate may now get a reply.
Replies longer than 5 s go to the portal in pieces of at most 4 s (its `play_pcm` limit),
in one speaker job.

### PC-side latency

| Change | Expected gain |
| --- | --- |
| Speech hangover 704 → 480 ms | 224 ms earlier end of activity after sustained quiet |
| First PCM block target 1.0 → 0.5 s | About 70–125 ms earlier dispatch when model audio arrives at 4–7× real time and the threshold controls dispatch |
| Stream no longer prepends 100 ms of zeros | 100 ms earlier signal onset with the fade and filter still applied |
| Half-duplex guard overlaps the guardian idle window | About 1.3–1.5 s sooner to accept the next utterance compared with the previous approximately 2.75 s window |

These are estimates from code and earlier measurements. The first three can
reduce onset latency by about 0.4–0.45 s on a streamed reply.

### Camera power and reconnects

CCC reads stock cmd 2009 over HTTP GET at binding and every five minutes while
connected. The stock 0–4 readings are battery levels. In the stock
`sdvcam` battery detector, level 5 is selected when
`/sys/class/focus_gpio/vbusdet_gpio` indicates USB power. The endpoint gives no
charge percentage or charging current. CCC logs the reading and warns at
levels 0 and 1. The desktop Connections tab shows the reading and any media
hold.

If a new boot replaces a bound boot, or media is unprepared while stock mode
is unusual, CCC waits at least 45 s and requires 5 s of a consistent idle
video or photo mode before preparation. A camera that keeps recording or
remains in an unusual mode stays on hold. With idle photo mode confirmed,
CCC uses the existing video-mode preparation path and checks that it has
settled. A camera that already reports prepared media can rejoin immediately.

The physical capture switch and boot status poll every 0.5 s during
conversation and every 2 s while idle. The portal itself closes the mic stream
on a physical mute. This cuts idle `/v1/state` polling from about 7,200 to 1,800
requests an hour. Lease renewal stays at 15 s.

### Voice recovery and health

Gemini connection and setup have a 20 s deadline. Transport and server errors
back off up to 30 s. Quota or rate-limit errors wait 30 s. Payload and
policy errors (400, 1007, 1008) back off from 5 to 60 s. Clear authentication
or missing-model errors mark voice health failing and retry every 10 minutes.
An explicit resume refusal clears the saved handle and reconnects with a
transcript summary. Two unexpected silent replies since the last PCM also
clear the handle. An empty completed mic turn with no sign of a model answer
counts as ignored speech. A missing completion, an answer with text but no
PCM, or a typed or system turn that completed with no PCM counts as a voice
failure. After 10 s without PCM during a partial reply, CCC queues its
buffered tail, records `stalled` and rebuilds the connection. Tool execution
pauses that watchdog and sending the tool result starts a new stall window.

Queued text turns keep their place through disconnects and wait for a camera
lease. Model replies discarded because the camera binding ended are counted.
Physical mute, microphone stream end and lease loss close the speech gate.
If a speaker job still has no terminal phase five seconds after its estimated
playback and tail, CCC requests cancellation and clears its local job.
Speaker refusals keep the portal's detail, including guardian reasons such
as `stock-pcm-format`. Three consecutive failed jobs mark the speaker failing
and trigger lease release and reacquisition. A finished job clears the failure streak.

The adult standalone deployment runs a silent check at the first idle
opportunity after each lease bring-up and after three hours between checks.
A separate Gemini connection requests one word and discards its returned PCM.
The camera operation is a read of speaker status. This checks the Gemini audio
response and the speaker control state. Audible playback is verified by a
conversation turn. The family deployment continues to use its local voice path.

`GET /v1/status` exposes `voice_health` (`ok`, `degraded`, `failing`) and
`voice_health_reasons`. It combines camera and mic state, the ages of the
last mic chunk, heard speech, nonempty Gemini PCM and successful speaker job,
plus the latest Gemini error and silent check. The Gemini status includes
`silent_replies`, `ignored_speech_turns`, `discarded_replies`, `last_error`,
`next_retry` (Unix seconds when backing off), and `canary`. Speaker status
includes `state`, `consecutive_failures`, `lease_recycles`, and
`last_finished_age_s`. Body status includes `battery` (`level`,
`external_power`, `warning`, `checked_at` in Unix seconds) and `media_hold`.
The open profile store reports `eyes.history.store.max_frames`.

## Memory (2026-11-16)

Cammy keeps lasting facts across conversations and C3 restarts (`host/c3/memory.py`):
- Gemini tools `remember`, `recall_memory`, `forget`. Each fact is kept in
  `private/c3/memory/facts.jsonl` (this PC, git-ignored) and as one note per fact in the
  shared Agent-Memory vault, `SERVE/MEMORY VAULT/bots/cammy/cammy-fact-<id>.md`
  (so `forget` deletes it, and Adam can see the facts in Obsidian). Recall searches only
  that folder: Gemini never reads the rest of the vault, since whatever it reads goes to
  Google. Hindsight was retired on 2026-11-23. Passwords, PINs, codes, keys and long
  numbers are refused.
- Every fresh connection starts with the newest 40 facts in the system instruction. They
  are kept out of the persona `base`, so a new fact does not drop a resumable session.
- The Gemini resume handle is saved to `private/c3/session.json` (about 2 h), and the
  last 12 h of conversation is reloaded after a restart for a fresh session's summary.
- The bank extracts facts in English (`retain_custom_instructions`); without it a test fact
  came back in Turkish. Live check: stored, found 5-10 s later, deleted.
- The brain retains facts from `[Cammy transcript]` that Gemini did not keep to
  `bot::cammy` too (`brain/CLAUDE.md`).
